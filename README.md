# DRMS — Disaster Response Management System

A **Capacitor-based offline-first React app** for coordinating disaster response volunteers. Works in the browser and as an Android APK. Reports are stored locally in IndexedDB and synced to a central PostgreSQL backend via HTTPS (ngrok tunnel), with optional P2P (LAN) device-to-device sync.

---

## Features

- **Offline-first** — Create and view reports with no internet connection using IndexedDB
- **Server sync** — Push/pull reports to/from a central PostgreSQL backend over HTTPS
- **P2P sync** — Sync directly with another device on the same LAN (no server required)
- **Conflict resolution** — Field-level CRDT merging: conflicting fields are flagged and resolved manually by the volunteer
- **Android APK** — Built with Capacitor; works on Android 7+ with HTTP cleartext support configured
- **Device identity** — Each device has a persistent UUID stored in `localStorage` used to track which device last modified each field

## Setup

### 1. Clone the repo

```bash
git clone https://github.com/shet-anirudh/MP_DRMS_ACM.git
cd MP_DRMS_ACM
```

### 2. Install dependencies

```bash
# Backend
cd server
npm install

# Frontend
cd ../client
npm install
```

### 3. Configure the database

Create a `.env` file in `server/`:

```env
DATABASE_URL=postgresql://user:password@host:5432/dbname
NODE_ENV=development
```


### 4. Start the backend

```bash
cd server
node server.js
```

Expected output:
```
PostgreSQL table ready
Server running on port 3001
```

### 5. Expose the backend via ngrok (required for Android)

```bash
ngrok http 3001
```

Copy the `https://` URL (e.g. `https://abc123.ngrok-free.app`) and update `client/src/services/sync.js`:

```js
const BASE_URL = 'https://napping-woven-iciness.ngrok-free.dev/';
```

> ⚠️ The ngrok free URL changes every time you restart ngrok. Update `BASE_URL` and rebuild.

### 6. Start the frontend (browser dev server)

```bash
cd client
npm run dev
```

```bash
npx cap open android
```

In Android Studio: **Build → Clean Project → Build APK**

### Android HTTP / CORS Notes

- `android/app/src/main/res/xml/network_security_config.xml` — allows cleartext HTTP traffic (needed for P2P sync with local IPs)
- `AndroidManifest.xml` — references the config and declares `INTERNET` + `ACCESS_NETWORK_STATE` permissions
- All server sync uses the ngrok `https://` URL — no cleartext needed for server sync
- The `ngrok-skip-browser-warning: true` header is sent on every request to bypass ngrok's browser interstitial page

## Sync Architecture

### Server Sync (`POST /sync`)

1. Client sends all local reports
2. Server merges each field individually using timestamp-based last-write-wins
3. If two different devices edited the same field at different times → **conflict** is flagged
4. Server returns all reports (merged)
5. Client stores merged reports to IndexedDB

### P2P Sync (`POST /p2p-sync`)

Same merge logic, but client sends directly to another device's IP on port 3001. No server required — works over LAN / hotspot.

### Conflict Resolution

Conflicts are flagged at the field level (`injuredCount`, `notes`, `location`). Each conflicted field stores:

```json
{
  "conflict": true,
  "versionA": { "value": 5, "timestamp": 1712345678, "updatedBy": "device-A" },
  "versionB": { "value": 3, "timestamp": 1712345999, "updatedBy": "device-B" }
}
```

The volunteer manually picks a version via the UI. The resolved field gets a new timestamp (`Date.now()`) so it wins on the next sync.

## Known Limitations

- **ngrok free tier** — URL changes on every restart; must update `BASE_URL` and rebuild APK
- **P2P sync** — Requires both devices to be on the same LAN/hotspot; enter peer IP manually; just a demo
- **IndexedDB** — Browser only; Capacitor's WebView on Android uses its own IndexedDB instance (data is local to the app)
